# Session settings

This reference lists current session values, where they live, and what to check after changing them. The repository has no central settings file or general session configuration schema.

Use the [participant package instructions](../participant/README.md) to install the participant CLI from `participant/`. Follow the [QuickStart](quickstart.md) and [kit README](../kit/README.md) for participant operation. The repository root builds the organizer CLI. See the [handoff-site README](../handoff-site/README.md) for site setup and operation.

## Settings, locations, and checks

Paths are repository-relative. Site content files are under `handoff-site/app/_content/`. Environment values use the ignored `.env` procedure in the [handoff-site README](../handoff-site/README.md).

| Setting and effect | Where to change it | Check |
| --- | --- | --- |
| Event identity, brief, and instructions | Content in [site.ts](../handoff-site/app/_content/site.ts), [participants.ts](../handoff-site/app/_content/participants.ts), and [organizers.server.ts](../handoff-site/app/_content/organizers.server.ts) `eventFacts` | Compare participant, organizer, print, and kit copy. Match dates, deadlines, and paths. |
| Live date, timezone, and ordered starts | Code in [live-state.ts](../handoff-site/app/_content/live-state.ts): `tokyoTimestamp`, `START_TIMES`, and `SESSION_STAGE_IDS` | Test just before and at each boundary in [live-state.test.ts](../handoff-site/tests/live-state.test.ts). Check the countdown and next-only advancement. |
| Stage guidance and fallback | Content in [live-content.server.ts](../handoff-site/app/_content/live-content.server.ts) `SESSION_STAGES`, [participants.ts](../handoff-site/app/_content/participants.ts) `journey`, [organizer-pack.server.ts](../handoff-site/app/_content/organizer-pack.server.ts) `afternoonRun`, `handoff-site/public/desk/`, and [session-fallback.html](../handoff-site/public/session-fallback.html) | Keep stage IDs and order aligned. Compare print and fallback copy. Check that earlier snapshots exclude later guidance. |
| Controlled rehearsal time | Environment value `LIVE_ALLOW_CONTROLLED_CLOCK`, read by [live-store.server.ts](../handoff-site/app/_content/live-store.server.ts) | Only the exact value `true` enables `now` overrides. Check rehearsal behavior with the value set and normal clock behavior when it is unset. |
| Local coach advancement token | Environment value `LIVE_COACH_TOKEN`, read by the [live route](../handoff-site/app/api/live/route.ts) | Missing configuration returns 503. A wrong token returns 401. Replay an authorized request and confirm one advance. The token protects POST requests, not coach-page access. In-memory state resets on server restart. |
| Submission destination | Environment value `SUBMISSION_FORM_URL`, read by [submission.server.ts](../handoff-site/app/_content/submission.server.ts) `configuredSubmissionFormUrl` | Check that an unset value omits the link. Check that configured URLs use HTTPS without embedded credentials. Check one synthetic receipt through the [intake workflow](phase1/intake-acceptance.md). |
| Recording selection, topics, and rights | External recipe fields defined by [data_products.py](../src/civ_workshop/data_products.py) `RECIPE_FIELDS` | Follow [data-product build and audit](phase3/participant-data-products.md). Check the parent hash, retained topics, attribution, and permissions. |
| EventSpec bindings and rules | Copy [Kashiwa](../examples/kashiwa/right_turn.yaml) or [Reims](../examples/reims/left_turn.yaml) examples and follow the [EventSpec schema](../schemas/civ.eventspec.v1.schema.json) | Follow [EventSpec rules](phase2/eventspec-cel-and-derive.md). Check fields and units, run a dry-run detection, and review event meaning against evidence. |
| Viewer paths and readiness policy | `layouts/` and doctor arguments in [participant_commands.py](../src/civ_workshop/participant_commands.py) | Check matching bag and layout time bounds and a writable workspace. Choose `pure-mcap` or `release-target` through the [doctor readiness policy](phase3/doctor-readiness-policy.md). `READY` alone does not qualify offline recovery. |
| Practice and evaluation labels | `civ score --labels` uses the participant scoring reference in [score_reference.py](../src/civ_workshop/score_reference.py). `civ score-batch --labels` uses sealed packs validated by [label_packs.py](../src/civ_workshop/label_packs.py). | Check source hashes, interval bounds, and mismatch rejection. Keep participant practice labels separate from organizer-only full truth. The current batch loader accepts exactly `kashiwa` and `reims`. See the [organizer label-pack contract](phase3/organizer-label-packs.md). |
| Intake deadline | Code in [intake.py](../src/civ_workshop/intake.py) `TOKYO_CUTOFF`, also used by [batch.py](../src/civ_workshop/batch.py). There is no cutoff flag. | Align site and provider wording. Test receipts before, at, and after the cutoff. Also test ties and resubmission in [test_intake.py](../tests/test_intake.py) and [test_batch.py](../tests/test_batch.py). |
| Build audience and static output | [build-audience.mjs](../handoff-site/scripts/build-audience.mjs), [package.json](../handoff-site/package.json), and [vite.config.ts](../handoff-site/vite.config.ts) | `npm run build` selects the public audience. The internal build is for review. The route split is a content boundary, not access control. Check restricted-route 404s and exported assets. The exporter copies asset directories, so audience selection alone does not qualify the output. |
| Post-event solutions | `POST_EVENT_SOLUTIONS_PREVIEW`, `POST_EVENT_SOLUTIONS_RELEASED`, [post-event-solutions.server.ts](../handoff-site/app/_content/post-event-solutions.server.ts) `solutionRelease`, and [solutions/page.tsx](../handoff-site/app/solutions/page.tsx) | Keep release flags unset during the session. The preview flag bypasses the app's release check in an internal build. The public build omits the route. Adapted answers need separate approval before release. |

## Changes that need code and new acceptance

The current `batch.py:_load_label_packs` requires exactly `kashiwa` and `reims`. New dataset membership needs code. Kit composition, fallback signals, and asset pins live in [kit_inventory.py](../src/civ_workshop/kit_inventory.py) and [kit_assembly.py](../src/civ_workshop/kit_assembly.py). Scoring policy in [score_reference.py](../src/civ_workshop/score_reference.py) also needs code, and a label-pack override does not change it. Participant dependencies and package contents live in [participant/pyproject.toml](../participant/pyproject.toml) and [participant/_build_backend.py](../participant/_build_backend.py).

Keep historical approval hashes and verifier pins in [release freeze](phase5/release-freeze.md), [legal acceptance](phase5/legal-risk-acceptance.md), `release_freeze.py`, and `workstation_qualification.py` unchanged. New sessions need their own acceptance evidence.

See [Make it your own](../MAKE-IT-YOUR-OWN.md) for one synthetic session example.
