# Phase 5 camera-context attendee-kit candidate

This candidate supersedes the Phase 4 attendee-kit bytes without replacing them. It retains the
accepted 13 signal MCAPs byte-for-byte and adds one camera-context MCAP per signal product: one
Kashiwa warm-up, seven Kashiwa development, and five Reims development products. Sealed products
are not members.

## Recorded topic inventory and calibration decision

The source inventory was resolved by `source_id`, and every source SHA-256 was checked before
processing.

- Kashiwa supplies compressed, raw, and Theora forms of the traffic-light camera plus a matching
  CameraInfo topic. The companion retains only
  `/sensing/camera/traffic_light/image_raw/compressed` and
  `/sensing/camera/traffic_light/camera_info`. Its `/tf_static` messages mix the camera transform
  with unrelated transforms and are excluded.
- Reims supplies `/zed/zed_node/rgb/image_rect_color/compressed` in all five selected chunks. No
  CameraInfo or separate calibration file was present. The companion retains only that compressed
  stream; calibration is recorded as `absent-not-inferred`. Static transforms are excluded rather
  than synthesized or carried inconsistently across chunks.

Signals, point clouds, maps, debug imagery, labels, truth, unrelated transforms, and organizer
paths are excluded from every companion and public manifest.

## Privacy and rights

All 26,244 selected frames were included in the review set. Matthieu Carré, event owner, approved
the exact 13-product set for registered CIV 2026 participant event use. The attributable approval
records completed inspection, confirms that redaction is not required, and binds the reviewed
frame-set hash. The approval file and reviewed frames remain outside git.

## Determinism and identity

Two independent external builds produced byte-identical MCAPs, sidecars, and set manifests. Each
tree contains 27 files and requires 5,424,077,234 bytes. The camera-context set SHA-256 is
`4250737318af51edec62bb4bd39d4c19444b97152b2885a3b40e0df68c770542`.

The set and sidecars bind the source hash, accepted signal-product hash, selected topics, matching
signal time bounds, calibration status, approval, message counts, byte sizes, and output hashes.
The accepted signal set remains independently pinned and is never regenerated by this workflow.

## Participant use

Participants open a signal MCAP and its same-source context companion together in Lichtblick and
use the existing dataset layout. PlotJuggler remains available for signal manipulation. Camera
context is an inspection aid only: video, frames, MCAPs, and evidence clips remain excluded from
metadata-only submissions.
